\section{Introduction et Architecture du Projet}
% =============================================================================

Ce projet implémente une chaîne complète de Machine Learning appliquée à la clientèle d'un e-commerce de cadeaux. L'objectif est double : prédire le départ des clients (\textit{churn}) par classification binaire, estimer leur valeur monétaire par régression, et segmenter la base par clustering non supervisé.

\subsection{Stack Technique}

\begin{itemize}[label=\color{headerblue}$\bullet$]
    \item \textbf{Language :} Python 3.x
    \item \textbf{Manipulation :} Pandas, NumPy
    \item \textbf{Prétraitement :} Scikit-learn (StandardScaler, KNNImputer, PCA, IsolationForest)
    \item \textbf{Modélisation :} Scikit-learn, XGBoost, Imbalanced-learn (SMOTE)
    \item \textbf{Métriques :} Accuracy, Precision, Recall, F1-Score, ROC-AUC, RMSE, R²
    \item \textbf{Déploiement :} Streamlit (application web interactive)
\end{itemize}

% =============================================================================
\section{Jeu de Données et Variables Cibles}
% =============================================================================

Le dataset comprend \textbf{4 372 clients} décrits par \textbf{52 features} (34 numériques, 18 catégorielles) issues de transactions réelles.

\begin{tcolorbox}[colframe=headerblue, title=Variables Cibles (fournies dans le dataset)]
\begin{itemize}
    \item \textbf{Churn} (feature n°34) : Binaire -- Indicateur de départ du client. \texttt{0 = fidèle}, \texttt{1 = parti}. Cette variable est native du fichier source et constitue la cible de classification.
    \item \textbf{MonetaryTotal} (feature n°4) : Float -- Somme totale dépensée par le client (£). Cette variable est native du fichier source et constitue la cible de régression.
\end{itemize}
\end{tcolorbox}

\subsection{Problématiques de Qualité Identifiées}

\begin{tcolorbox}[colframe=warningred, title=Défis de qualité]
\begin{itemize}
    \item \textbf{Valeurs manquantes :} Age (30\%), formats de dates inconsistants (UK, ISO, US)
    \item \textbf{Aberrantes :} SatisfactionScore $\in \{-1, 99\}$, SupportTicketsCount $\in \{-1, 999\}$
    \item \textbf{Fuites potentielles :} ChurnRisk et RFMSegment (proxies directs de la cible Churn)
    \item \textbf{Déséquilibre :} Churn à 32,8\% (modéré, traité par SMOTE)
\end{itemize}
\end{tcolorbox}

\section{Prétraitement : Chaîne de Transformation}
% =============================================================================

\subsection{Stratégie Anti Data Leakage}

Toute statistique (moyenne, écart-type, imputation, détection d'outliers, target encoding) est \textbf{apprise uniquement sur le train} (80\%) et appliquée sur le test (20\%). Cette règle est scrupuleusement respectée pour éviter toute fuite d'information entre les ensembles.

\subsection{Feature Engineering}

Trois ratios métier sont créés \textbf{avant le split} :
$$\text{MonetaryPerDay} = \frac{\text{MonetaryTotal}}{\text{Recency} + 1}, \quad \text{AvgBasketValue} = \frac{\text{MonetaryTotal}}{\text{Frequency}}, \quad \text{TenureRatio} = \frac{\text{Recency}}{\text{CustomerTenure} + 1}$$

\subsection{Encodage des Variables Catégorielles}

\begin{itemize}
    \item \textbf{One-Hot :} CustomerType, FavoriteSeason, Region, Gender, AccountStatus, ProdDiversity, WeekendPref
    \item \textbf{Ordinal :} SpendingCat, LoyaltyLevel, AgeCategory, BasketSize (mapping explicite vers $0,1,2,3$ avec \texttt{np.nan} pour les valeurs inconnues, compatibles avec KNNImputer)
    \item \textbf{Target Encoding :} Country (moyenne de Churn par pays, calculée strictement sur l'ensemble d'entraînement uniquement)
\end{itemize}

\subsection{Détection d'Outliers : IsolationForest}

L'algorithme est ajusté (\texttt{fit}) uniquement sur les features numériques du jeu d'entraînement avec \texttt{contamination=0.06}. Les outliers identifiés (210 lignes, soit 6\%) sont supprimés du train ; le jeu de test est préservé intact.

\subsection{Suppression des Features Constantes}

Après le filtrage par IsolationForest, les colonnes de variance nulle (toutes identiques) sont supprimées. Exemple : NewsletterSubscribed, RFMSegment, SpendingCategory, PreferredTimeOfDay, WeekendPreference, BasketSizeCategory, ProductDiversity, Country\_TargetEnc.

\subsection{Imputation : KNNImputer}

Les valeurs manquantes (notamment les \texttt{np.nan} des mappings ordinaux et les Ages aberrants) sont remplacées par la moyenne des 5 plus proches voisins ($k=5$) calculée dans l'espace des features standardisées. L'imputer est sérialisé (\texttt{joblib}) pour être réutilisé en inférence.

\subsection{Multicolinéarité : Variance Inflation Factor (VIF)}

Après imputation, le VIF est calculé pour chaque feature selon :
$$\text{VIF}_j = \frac{1}{1 - R^2_j}$$
où $R^2_j$ est le coefficient de détermination de la régression de la feature $j$ sur les autres. Les features avec $\text{VIF} > 10$ sont supprimées.

\textbf{Features supprimées par le VIF :} Recency, Frequency, CustomerTenureDays, FirstPurchaseDaysAgo, PreferredHour, UniqueProducts, UniqueDescriptions, AvgProductsPerTransaction, UniqueCountries, NegativeQuantityCount, CancelledTransactions, TotalTransactions, UniqueInvoices, AvgLinesPerInvoice, Age, AgeCategory, LoyaltyLevel, RegYear.

\textbf{Features conservées après VIF :} 19 variables (MonetaryTotal, MonetaryAvg, MonetaryStd, MonetaryMin, MonetaryMax, TotalQuantity, AvgQuantityPerTransaction, MinQuantity, MaxQuantity, PreferredDayOfWeek, PreferredMonth, WeekendPurchaseRatio, AvgDaysBetweenPurchases, SupportTicketsCount, SatisfactionScore, MonetaryPerDay, AvgBasketValue, et les colonnes one-hot résiduelles).

\subsection{Réduction de Dimension : Analyse en Composantes Principales (PCA)}

% ============================================================
% SECTION : RÉCAPITULATIF DU PIPELINE (CORRIGÉE)
% ============================================================

Un \texttt{StandardScaler} centre-réduit les données ($\mu=0, \sigma=1$), suivi d'une PCA à 10 composantes. La variable cible \texttt{Churn} n'est jamais standardisée (c'est l'objectif à prédire, pas une feature).

\begin{tcolorbox}[colframe=headerblue, title=Évolution des dimensions du dataset]
\begin{center}
\renewcommand{\arraystretch}{1.4}
\begin{tabular}{llcl}
\toprule
\textbf{Étape} & \textbf{Dimensions} & $\rightarrow$ & \textbf{Action} \\
\midrule
Entrée brute & (4\,372, 52) & $\rightarrow$ & Chargement du CSV original \\
Après split (train) & (3\,497, 69) & $\rightarrow$ & \texttt{train\_test\_split} (80\%) \\
Après IsolationForest & (3\,287, 45) & $\rightarrow$ & Suppression des outliers (6\%) \\
Après nettoyage & (3\,287, 37) & $\rightarrow$ & Suppression features constantes \\
Après VIF & (3\,287, 19) & $\rightarrow$ & Suppression multicolinéarité (VIF>10) \\
Après standardisation & (3\,287, 19) & $\rightarrow$ & \texttt{StandardScaler} (fit sur train) \\
Après PCA & (3\,287, 10) & $\rightarrow$ & 10 composantes (77,3\% variance) \\
\bottomrule
\end{tabular}
\end{center}
\end{tcolorbox}

\textbf{Légende des étapes :}
\begin{itemize}[label=\color{headerblue}$\bullet$]
    \item \textbf{52 $\rightarrow$ 69 colonnes :} Augmentation due au one-hot encoding (CustomerType, Region, Gender, etc.)
    \item \textbf{69 $\rightarrow$ 45 colonnes :} IsolationForest supprime 210 lignes d'outliers ; les colonnes passent de 69 à 45 car seules les features numériques sont conservées pour la détection d'anomalies
    \item \textbf{45 $\rightarrow$ 37 colonnes :} Suppression des 8 features de variance nulle (NewsletterSubscribed, RFMSegment, SpendingCategory, etc.)
    \item \textbf{37 $\rightarrow$ 19 colonnes :} Filtrage par VIF > 10 (suppression de Recency, Frequency, CustomerTenureDays, etc.)
    \item \textbf{19 $\rightarrow$ 10 colonnes :} Réduction par PCA pour la classification
\end{itemize}

\section{Modélisation Avancée}
% =============================================================================

\subsection{Classification : Chaîne SMOTE + GridSearchCV}

Pour palier le déséquilibre des classes, un \textbf{Pipeline Imbalanced-Learn} est mis en place :
\begin{enumerate}
    \item \textbf{SMOTE} (Synthetic Minority Over-sampling Technique) : génération d'exemples synthétiques de la classe minoritaire (Churn=1) par interpolation entre voisins proches
    \item \textbf{Classifieur} : entraînement avec recherche d'hyperparamètres par validation croisée (GridSearchCV, \texttt{cv=5}, \texttt{scoring='f1'})
\end{enumerate}

Cette architecture garantit que le sur-échantillonnage \textbf{ne s'applique que sur les folds d'entraînement}, évitant ainsi la fuite de données entre train et validation interne.

\section{Déploiement : Application Streamlit}
% =============================================================================

L'industrialisation repose sur une application web interactive développée avec \textbf{Streamlit}, framework Python léger dédié au Machine Learning et à la Data Science.

\subsection{Pourquoi Streamlit ?}

\begin{itemize}[label=\color{headerblue}$\bullet$]
    \item \textbf{Pure Python :} Un seul fichier \texttt{app.py}, sans HTML/CSS/JS séparé
    \item \textbf{Widgets natifs :} Sliders, métriques, tableaux, graphiques intégrés
    \item \textbf{Hot reload :} Modification du code reflétée instantanément dans le navigateur
\end{itemize}

\subsection{Architecture de l'Application}

L'application lit directement les données de test déjà prétraitées (\texttt{X\_test\_pca.csv}, \texttt{X\_test\_scaled.csv}).

\begin{tcolorbox}[colframe=headerblue, title=Flux de l'inférence]
\texttt{X\_test\_pca.csv} $\rightarrow$ Modèle Churn (XGBoost) $\rightarrow$ Probabilité + Classe \\
\texttt{X\_test\_scaled.csv} $\rightarrow$ Modèle Monetary (RandomForest) $\rightarrow$ Montant prédit \\
\texttt{X\_test\_pca.csv} $\rightarrow$ Modèle Cluster (K-Means) $\rightarrow$ Segment client
\end{tcolorbox}

\subsection{Fonctionnalités Implémentées}

\begin{itemize}[label=\color{successgreen}$\checkmark$]
    \item \textbf{Métriques globales :} Affichage d'Accuracy, Precision, Recall, F1-Score en temps réel
    \item \textbf{Tableau de résultats :} Présentation des 875 prédictions avec Churn réel vs prédit, probabilité, montant réel vs prédit, et cluster attribué
    \item \textbf{Export CSV :} Téléchargement complet des résultats
    \item \textbf{Visualisations :} Matrice de confusion, scatter plot régression (réel vs prédit), projection des clusters sur PC1/PC2
    \item \textbf{Filtre client :} Recherche par identifiant (0 à 874) avec interprétation du risque (Faible / Moyen / Élevé / Critique)
\end{itemize}

\section{Conclusion}
% =============================================================================

Ce projet démontre la maîtrise complète du cycle de vie d'un projet Machine Learning appliqué au Retail. De l'exploration des données brutes jusqu'au déploiement d'une application web interactive avec Streamlit, chaque étape respecte les bonnes pratiques : absence de fuite de données, validation croisée, rééquilibrage contrôlé par SMOTE, et évaluation sur données réellement indépendantes.

Les résultats obtenus (84\% accuracy, F1=0,75, $R^2=0,847$) valident la pertinence des techniques employées et offrent une base décisionnelle exploitable par les équipes marketing pour réduire le taux de départ et optimiser le chiffre d'affaires.
